# Sprint 02.6 — review and catalogue operations

Status: `LOCAL IMPLEMENTATION VERIFIED`

Submissions own structured proposed changes and create a first-class ReviewCase.
Decisions support approve-new, match-existing, approve-correction,
needs-more-information, reject, and withdraw. Every material action records actor,
request, old/new values where relevant, time, and rationale in the audit stream.

A reviewer-approved barcode becomes trusted only when no other trusted active claim
owns the normalized value. Collisions create a `CONFLICTED` claim and preserve the
existing trusted resolver. Merge operations retain the old VAR, record its survivor,
create an IdentityRelationship, and deliberately remap coverage.

An operator UI and staffing workflow are not part of 02.6; the reviewed API and
domain operations are the implemented operator surface.
